LotKeys Privacy Policy

Effective November 9, 2026 · Controlled pilot

LotKeys helps dealership teams maintain vehicle profiles, prepare Marketplace listings, store account preferences, and communicate with approved users. This policy describes the web experience and its optional Android phone, PC-relay and background-upload functions.

Information LotKeys uses

LotKeys may use your Google account identifier and email address, your LotKeys display name, optional phone number and profile photo, Store membership, vehicle and listing information, saved posting locations, awards, and Chat content you choose to create.

Where information is stored

The current application stores working data in your browser and stores portable account or dealership data in Google Drive files that you or Store administration authorize. The static application is delivered through GitHub Pages. Do not place customer financial information, passwords, payment-card details, or other data that LotKeys does not request into free-text fields.

Google account and Drive access

LotKeys uses Google Identity Services and Google Drive APIs only after you authorize access. The current pilot requests Store Drive access plus the private Drive app-data permission during controlled team testing so a Store Code can locate an existing shared Store folder, LotKeys can create, find, read, update, and organize the account, private Hub, and Store files used by its workflows, and the encrypted phone-pairing relay can use its hidden application-data space. OAuth Test User approval does not grant access to a Store folder; Store administration must separately approve and provision your Google account. Ordinary and Trusted users receive view access to official Inventory plus write access to their own Listings, More, and Messaging workspace. Full Drive access is a restricted Google OAuth scope. Public release requires the applicable Google verification and security review; reducing access to selected files must be validated against all existing account and dealership workflows before changing authorization.

Chat and calls

Current Chat message envelopes are encrypted in the browser and relayed through the test Store/Drive design. Voice and video features use browser media and peer-connection capabilities when you actively start or accept a call. The team-test implementation has not completed an independent production security audit and should not be used for highly sensitive communications.

Device SMS/MMS history remains phone-sourced. While connected, the active LotKeys tab temporarily caches six recent messages for each of ten recent unblocked conversations, renewing snapshots within five minutes. This cache clears on disconnect, Google account changes or page closure. Current MMS can display inline; older unsaved media uses View photo. Temporary preview bytes use in-memory object URLs and clear when the conversation closes, the phone disconnects, the account changes or the page closes. Unsaved media is not prefetched by the recent-message cache. Pressing 💾 remains the separate retention action.

Android background saves and browser data

Background Vehicle Profile saves require separate approval for the same Google account's Drive access. Android retains original photos, videos and documents in private app storage with the account, Store, destination and edit checks needed to finish that save. Originals are released after the complete Drive save is confirmed; conflicted, cancelled or incomplete jobs retain files for review. Removing the app or clearing its storage can destroy retained originals. Background scheduling depends on Android, network and battery conditions.

The Android launcher opens the same HTTPS TEST address through your browser. It does not import or clear browser records. Continue using the same browser to retain local drafts, media and settings. A small timing record for the latest Android handoff is saved with the Vehicle Profile; it contains times, byte counts and file counts, without message content. Optional Firebase wake support remains inactive unless separately configured; it is not the storage system for Vehicle originals.

Facebook Post Buddy

The optional Chrome extension reads a Listing selected from an open LotKeys tab and helps fill an open Facebook Marketplace form. It does not press Facebook’s final Next or Publish action. Facebook is a separate service with its own policies.

Sharing and retention

Store data is visible according to Google Drive permissions and LotKeys Store roles. A conversation may remain in a participant’s own archive after that participant leaves a Store. You can remove local site data through browser settings and remove personal LotKeys files from Google Drive. Store-held records may require Store administration to remove them.

Account deletion

Request account and personal-data deletion. The controlled pilot uses a manual identity-verified request to the LotKeys Creator. Dealership-owned records, other participants' copies and pending local originals require the separate review explained on that page. This pilot process still needs production verification before public launch.

Your choices

You may leave the optional phone number blank, decline Google permissions, disconnect from a Store, remove the local Lock Screen, clear browser data, or stop using the application. Features that need a declined permission will not work.

Security and changes

LotKeys uses HTTPS on its published site and continues to add access control, audit, rate-limit, and server-side authorization protections before public launch. This policy may change as those services are introduced.

Hub records and Android phone connection

Hub contacts, category assignments, number-blocking state, structured buying details, saved notes, reminders, appointments and documents are retained records. They use your owned, unshared personal Lot-Keys Account/Hub folder in Google Drive. Standalone reminders use a dedicated private Reminders folder and may optionally link to a Contact, phone number or Vehicle Profile. Contacts, notes, phone-number sorting and calendar metadata are also cached in this browser under your Google account identity. This test release does not add a separate application-level encryption key for those retained Hub records; use a trusted, secured device.

The optional Android test application can read the phone's SMS/MMS index, message history and selected MMS attachment bytes, optionally look up existing Android contact names, and submit a plain SMS only when the user presses Send. For photos, voice memos and documents, it prepares temporary private-cache files and opens the existing default messaging app so the user can review the recipient and press Send there. It does not become the default messaging application, write or delete the phone's message database, access existing private RCS history, create Android contacts, or block a number at the operating-system level. LotKeys Blocked hides numbers from normal Hub views and Hub alerts; Android's messaging app remains responsible for phone-level blocking and notifications. LotKeys unread acknowledgements store bounded local thread/message markers without copying message bodies or changing Android's native unread state.

Phone/computer discovery uses the same authorized Google account. The Android foreground service uses the application's private Google Drive app-data scope to keep pairing available when the phone browser closes. Pairing offers contain short-lived public-key and device-label information. Choosing the Google account on the PC creates, reads, and deletes a two-minute probe containing only a random identifier and timestamps. During an active session, message and media requests/responses are end-to-end encrypted before short-lived transport files enter the application's hidden Google Drive data area; processed and expired transport files are deleted. Normal phone history is not copied into a customer Drive folder or retained as an independent PC archive. Pressing 💾 creates a deliberate, separate retained copy in the selected Contact folder, with duplicate-source protection. PC notification-sound preferences and custom clips are backed up to the authorized personal Account Storage with the current settings workflow; automatic LotKeys Chat sounds are suppressed on Android. This test has not completed an independent security audit.

Contact deletion removes its Hub data and private Drive folder, linked Hub appointments and ordinary number sorting; an explicitly blocked number stays in Blocked until it is unblocked. A linked reminder remains as a standalone task with its Contact link cleared. Deletion does not remove downloaded/printed copies, phone messages or exported calendar copies. Camera captures are not intentionally added to the photo gallery. Use fictional records while testing; this is not an approved system for SINs, identity-number collection or financing decisions.
